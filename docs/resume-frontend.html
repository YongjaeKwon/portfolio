주요 경험

  • 문제새 CE를 등록할 때 직전에 조회한 CE의 첨부파일 그룹이 화면에 남아, 이전 사람의 첨부파일이 새 데이터에 연결될 수 있었습니다.
  • 해결 방향화면을 열 때 값만 비우는 대신 Vue 인스턴스마다 새로운 상태를 만들고, 서버 저장 단계에서도 잘못된 연결을 한 번 더 막았습니다.
  • 구현공통 객체의 얕은 복사를 상태 생성 함수로 바꾸고 등록 · 상세 조회 · 조회 실패 시 첨부 상태를 명시적으로 초기화했습니다. 서버는 이미 다른 CE가 사용하는 첨부파일 그룹이면 저장을 거부하도록 검증을 추가했습니다.
  • 결과화면 이동 뒤 이전 첨부파일이 다시 나타나는 원인을 제거하고, 화면 오류가 저장 데이터의 잘못된 연결로 이어지지 않도록 이중으로 막았습니다.
대량 다운로드의 진행 상태 UI와 비동기 처리

  • 해결 방향압축 속도만 높이는 대신 HTTP 요청과 장시간 파일 작업을 분리하고, 화면이 작업 상태를 이어서 확인하도록 흐름을 바꿨습니다.
  • 구현Spring 비동기 작업이 작업 ID를 먼저 반환하고, Vue 화면은 대기 · 진행 · 완료 · 실패 상태를 조회했습니다. 작업 ID를 브라우저에 보관해 새로고침 뒤에도 같은 작업을 다시 찾도록 했습니다.
  • 결과HTTP 연결을 계속 유지하지 않고도 사용자가 진행 상태를 확인하고, 완료된 파일만 내려받을 수 있는 사용자 흐름으로 바꿨습니다.
