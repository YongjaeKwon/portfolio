# B2B 협력사 포털(PPS)

본사와 약 500개 협력사가 등록·계약과 현장 엔지니어의 교육·자격·증빙을 처리하는 포털입니다. 초기 구축에 참여해 Vue 화면, Spring Boot API와 MyBatis 쿼리를 개발하고 운영·배포를 맡았습니다.

- 백엔드·DB: Java 21 · Spring Boot · MyBatis · MariaDB · Oracle
- 프론트엔드: JavaScript · Vue 2
- 상태 공유·배포: Hazelcast · Jenkins

## 새로고침 후에도 진행 상황을 확인하는 대량 다운로드

첨부파일 300~400건을 압축하는 동안 요청이 오래 유지되고 진행 상황을 알기 어려웠습니다. 압축 요청을 받으면 작업 번호를 먼저 반환하고 실제 압축은 Spring의 비동기 실행기로 처리하도록 바꿨습니다.

압축 요청과 상태 조회가 서로 다른 WAS 인스턴스에 전달돼도 같은 작업을 확인할 수 있어야 했습니다. 작업 번호별 진행·완료·실패 상태를 Hazelcast에 저장해 같은 호스트의 WAS 인스턴스가 공유하도록 했습니다. 화면은 주기적으로 상태를 조회하고 브라우저에 저장한 작업 번호로 새로고침 후에도 기존 작업을 찾습니다. 완료된 파일은 별도 요청으로 내려받고 다운로드 후 또는 보관 기한이 지나면 임시 파일을 정리합니다.

## 새 엔지니어에게 이전 첨부파일이 연결되는 오류 수정

새 엔지니어를 등록할 때 이전 사람의 첨부파일이 연결되는 오류가 있었습니다. 공통 객체를 얕게 복사하면서 Vue 인스턴스들이 같은 첨부파일 정보를 참조한 것이 원인이었습니다.

Vue 인스턴스마다 상태 객체를 새로 만들고 등록·조회에 실패하면 첨부파일 정보를 초기화했습니다. 서버에서도 다른 재직 엔지니어의 첨부파일을 연결하려 하면 저장을 거부했습니다. 센터를 옮긴 엔지니어를 재등록할 때는 미사용 계정의 파일을 이어 쓸 수 있도록 기존 예외를 유지했습니다.

## 비밀번호 초기화의 반복 발송과 인증번호 재사용 방지

비밀번호 초기화 인증번호를 반복 요청해도 어느 WAS에서든 같은 재발송 제한을 적용하도록 했습니다. Hazelcast에서 사용자별 발송 제한을 공유해 동시 요청 중 하나만 처리하도록 구성했습니다.

사용자별 제한 기록을 putIfAbsent로 등록해 동시에 들어온 요청이 같은 제한을 통과하지 못하게 했습니다. TTL로 유효기간을 두고 만료된 기록은 저장값이 바뀌지 않은 경우에만 삭제해 새 요청의 제한이 사라지지 않게 했습니다.

인증번호는 DB에서 일치 여부 확인과 사용 처리를 한 번에 수행해 재사용을 막았습니다. 인증번호·문자 본문은 API 응답에서 제외하고 문자 발송 요청 저장이나 비밀번호 변경에 실패하면 성공으로 반환하지 않도록 했습니다. 동시 요청·만료 경계·인증번호 재사용·실패 응답의 단위 테스트를 작성했습니다.

## Jenkins 배포 작업 구성

소스 반영·Gradle 빌드·서버 전송·백업·두 WAS 인스턴스 순차 배포를 담당자가 실행하는 Jenkins 작업으로 연결했습니다. 개발·운영 작업을 구분하고 단계별 실행 기록을 남겼습니다.

## 본사 계정 관리와 부서 변경 시 잔여 업무 확인

본사 계정 발급과 사내 시스템 전송을 한 관리 화면에서 처리하도록 화면·API를 개발했습니다. 부서·등급·계정 중복을 검사하고 발급·수정 후 연동 결과를 표시했습니다.

계정을 사용 중지하거나 부서를 바꿀 때 남은 재고·서비스 업무를 조회하고 잔여 업무가 있거나 API 조회에 실패하면 저장을 막았습니다. 부서 변경은 연동 시스템의 사용자·부서가 존재하는지 확인한 뒤 반영했습니다. 사용자 정보가 정확히 한 건 수정됐는지 검사하고 관련 요청 정보에도 같은 부서코드를 반영했습니다.

## 알림톡 발송 정책과 추가 수신자 관리

계정·교육·설문·공지 등 업무에 흩어진 발송 조건을 정책별로 관리하도록 바꿨습니다. 발송 여부·템플릿·추가 수신자와 수신 설정을 관리하는 화면·API, 변경 이력 저장을 개발했습니다.

기본 수신자와 추가 수신자를 합칠 때 엔지니어 ID 기준으로 중복을 제거하고 기본 수신자의 템플릿을 우선 적용합니다. 추가 발송을 끄면 대상 조회를 생략하는 분기와 중복 수신자 처리를 단위 테스트로 확인했습니다.

## 완료 계약서 전달과 발송 결과 추적

계약이 완료됐는지 확인한 뒤 문서를 첨부해 센터장에게 이메일을 보내는 기능을 개발했습니다. 발송 요청과 성공·실패·오류 내용을 이력으로 남겨 운영자가 결과를 확인하도록 했습니다.

## 센터별 교육 명단 제출과 참석 현황 관리

센터의 명단 제출과 관리자의 참석 현황·엑셀 다운로드를 연결했습니다. 업로드한 명단에서 다른 센터 소속이거나 이미 등록된 엔지니어를 제외 대상으로 안내합니다. 현황은 제출 완료한 명단을 기준으로 집계하고 미제출 센터와 구분합니다.

사내 소스와 실제 업무 화면·데이터는 공개하지 않습니다.
