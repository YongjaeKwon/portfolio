# B2B 협력사 포털(PPS)

> 공개용 설명입니다. 실제 사내 코드, 운영 URL, 계정·고객사 정보와 저장 데이터는 제외했습니다.

약 500개 협력사와 824개 현장 엔지니어 계정이 파트너 등록, 계약, 교육, 설문, 게시판과 문서 업무에 사용하는 운영 포털입니다. Vue 화면과 Spring Boot API, MyBatis 쿼리를 함께 개발하고 배포·운영까지 담당하고 있습니다.

## 상세 사례

### 1. 대량 첨부파일 다운로드를 작업 단위로 분리

첨부파일 300~400건을 한 번에 압축할 때 HTTP 요청이 오래 유지됐고, 사용자는 작업이 진행 중인지 실패했는지 알기 어려웠습니다. 기존 파일 선택 방식은 유지하면서 새로고침과 실패 상황까지 같은 작업으로 이어져야 했습니다.

압축을 브라우저 요청에서 분리하고 서버가 작업 ID를 먼저 반환하도록 바꿨습니다. 화면은 2초 간격으로 상태를 확인하고, 완료된 결과는 별도 요청으로 내려받도록 구성했습니다. 작업 ID를 브라우저에 보관해 새로고침 이후에도 진행 상태와 결과 파일을 다시 확인할 수 있게 했습니다.

이를 통해 장시간 HTTP 요청 점유를 줄이고, 사용자가 대기·진행·완료·실패 상태를 구분한 뒤 결과를 내려받는 흐름을 만들었습니다.

```js
const jobId = await startArchive(selectedIds);
sessionStorage.setItem("archiveJobId", jobId);

const job = await getArchiveStatus(jobId);
if (job.status === "DONE") downloadArchive(jobId);
if (job.status === "ERROR") showRetryGuide();
```

### 2. Vue 화면 사이에 남던 공통 상태 분리

여러 관리 화면이 같은 공통 스크립트의 중첩 객체를 얕게 복사해 사용하면서, 이전 화면의 조회 조건과 표시 값이 다른 화면에 남는 문제가 있었습니다.

공통 API는 유지하되 화면이 생성될 때마다 중첩 객체까지 새로 반환하는 상태 팩토리로 교체했습니다. 화면을 다시 열거나 탭을 전환할 때도 같은 기준으로 초기화하도록 정리했습니다.

서로 다른 Vue 인스턴스가 중첩 상태를 공유하지 않게 되어 이전 화면의 조건이 섞이는 문제를 제거했습니다.

```js
const createInitialState = () => ({
  filters: { keyword: "", status: "ALL" },
  selectedRows: [],
  pageTitle: { main: "", sub: "" },
});
```

### 3. 분리돼 있던 본사 계정 발급 절차 통합

사내 계정과 포털 계정을 각각 만든 뒤 발급 결과를 별도 DB에 반영하던 절차를 하나의 관리 화면으로 모았습니다. 조직·아이디 중복을 먼저 확인하고 사용자와 사원 정보를 같은 트랜잭션 범위에서 저장한 뒤, 성공한 정보만 사내 시스템으로 전달하도록 구성했습니다.

사내 계정 생성, 포털 계정 생성과 별도 정보 반영으로 나뉘어 있던 과정을 한 화면의 발급 흐름으로 통합해 운영하고 있습니다.

### 4. 알림톡 발송 조건과 수신자 처리 공통화

기능마다 흩어져 있던 발송 조건과 수신자 조회를 공통 서비스로 옮겼습니다. 발송 여부와 대상 조건은 DB 설정에서 조회하고, 중복 수신자는 공통 단계에서 제거하도록 했습니다. 정책 결과에 영향을 주는 주요 분기는 단위 테스트로 확인했습니다.

정책이 바뀔 때 여러 업무 코드를 함께 수정하지 않고 공통 설정과 서비스에서 변경 지점을 관리할 수 있게 했습니다.

### 5. 반복 배포 순서를 Jenkins 작업으로 정리

소스 반영, Gradle 빌드, 서버 전송, 기존 파일 백업과 두 WAS 배포를 매번 수동으로 수행하던 절차를 Jenkins 작업과 스크립트로 연결했습니다. 전용 배포 서버가 없는 환경에서 개발·운영 작업을 나누고, 두 서버는 정해진 순서대로 배포하도록 구성했습니다.

반복 배포를 같은 순서로 실행하고 단계별 성공 여부와 실행 기록을 확인할 수 있게 했습니다.

## 사용 기술

Vue, JavaScript, Spring Boot, Spring Security, MyBatis, MariaDB, Gradle, Jenkins, Linux, Tomcat

사이트에는 업무 맥락과 설계 판단을 설명하기 위한 축약 코드만 표시합니다. 실제 클래스명, 테이블명, API 주소, 인증 정보와 고객사별 정책은 공개하지 않습니다.
