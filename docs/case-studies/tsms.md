# 현장 A/S 접수·처리 시스템

> 공개용 정리입니다. 내부 코드, 고객사별 상세 정책, 운영 URL, 계정, 환경 정보는 제외했습니다.

- 문제: AS 접수, 동의, 전자서명이 여러 디바이스와 화면을 거치며 상태가 끊길 수 있었습니다.
- 만든 것: A/S 접수와 알림 발송 결과 확인 화면을 개선했으며, 모바일 동의와 전자서명 기능은 개발 중입니다.
- 결과: 완료된 범위에서는 접수 번호를 기준으로 접수 정보와 알림 상태가 조회되도록 화면 상태와 조회 조건을 맞췄습니다.

## 프로젝트 개요

A/S 접수, 상담, 이관, 배정, 알림 상태 확인 업무를 처리하는 WebSquare/JSP 기반 운영 시스템입니다. 접수 정보와 알림 상태가 데스크톱 관리자 화면에서 같은 접수 번호를 기준으로 이어져야 했고, 모바일 동의와 전자서명 기능은 개발 중입니다.

이 프로젝트에서는 내부 담당자가 접수 상태와 후속 처리를 확인하고, 필요 시 알림 발송 결과와 실패·대기 상태를 함께 확인하는 흐름을 다뤘습니다.

## 구현한 것

- WebSquare/JSP 기반 데스크톱·모바일·태블릿 업무 화면
- A/S 접수, 이관, 배정, 상담, 진행상태 조회 화면 일부 개선
- 알림 발송 결과, 실패, 대기, 재처리 상태 확인 흐름
- 연계 포탈의 조회 조건과 상태값 확인 및 화면 표시 보완
- 모바일 동의와 전자서명 기능 개발 중

## 해결해야 했던 문제

A/S 업무는 접수, 상담, 배정, 알림 상태 확인처럼 여러 단계가 이어집니다. 한 단계에서 입력된 정보가 다음 화면에서 다른 기준으로 조회되면 담당자가 처리 상태를 잘못 판단할 수 있습니다.

또한 개발 중인 모바일 동의와 전자서명 기능은 화면 폭과 입력 방식이 데스크톱과 달라 상태값과 조회 조건을 더 세밀하게 확인해야 했습니다. 사용자가 어디서 막혔는지 알 수 있도록 상태와 예외를 화면에 분명히 반영하는 것이 중요했습니다.

## 구현한 기능

### AS 접수 및 이관/배정

- AS 접수 목록과 상세 화면 개선
- 접수 이관, 담당자 배정, 센터 검색 조건 처리
- 상담 및 AS 접수 흐름에서 상태별 화면 분기 개선
- 진행상태 조회 조건과 상세 화면 데이터 연결 점검

### 모바일 동의와 개인정보 동의

- 모바일 동의 화면은 개발 중인 기능으로 분리해 정리
- 개인정보 동의 상태별 다음 단계 진입 조건 확인
- 접수 번호와 사용자 정보 기준으로 후속 화면이 이어지도록 조회 조건 정리

### 태블릿 전자서명

- 태블릿 환경에서 사용하는 서명 입력 화면 개발 중
- 서명 저장 결과, 재시도, 완료 상태 표시 흐름 확인 중
- 모바일/태블릿 화면에서 동일 접수 번호 기준으로 동의와 서명 상태가 이어지는지 점검 중

### 알림 발송 상태

- 알림 발송 조건, 발송 결과, 실패·대기 상태 화면 반영
- 알림 발송 결과가 사용자 화면에 남도록 상태 처리

## 기술적으로 신경 쓴 부분

현장 업무 화면은 사용자가 중간에 멈추거나 잘못 입력했을 때 복구할 수 있어야 합니다. 완료된 접수와 알림 화면에서는 사용자가 직접 수정할 수 있는 오류와 시스템 연동 실패를 구분해 화면 상태를 정리했습니다.

개발 중인 모바일 동의와 전자서명 화면은 같은 접수 번호와 접수 상태를 기준으로 연결되어야 했습니다. 따라서 화면 초기화, 조회 파라미터, 상세 데이터, 저장 이후 재조회 흐름이 같은 기준으로 동작하는지 확인하고 있습니다.

외부 메시지 발송 기능은 요청 성공과 실제 발송 결과가 다를 수 있습니다. 발송 결과를 성공·실패·대기·재처리 상태로 분리해 화면에 반영하고, 재처리나 실패 확인이 필요한 케이스를 운영자가 바로 구분할 수 있게 했습니다.

## 검증 방식

- 접수 유형별 필수값과 후속 단계 진입 조건 확인
- 개발 중인 모바일 동의와 전자서명은 접수 번호와 상태값 기준으로 별도 확인
- 데스크톱 화면이 같은 접수 번호를 기준으로 조회되는지 점검
- 외부 메시지 발송 성공, 실패, 대기 상태가 화면에 맞게 표시되는지 확인
- 권한 또는 센터 조건 변경 후 목록과 상세 화면의 조회 범위가 일치하는지 확인

## 배운 점

현장 업무 시스템은 화면 하나의 완성도보다 단계 간 연결이 더 중요했습니다. 접수 이후 알림과 상태 조회가 같은 접수 번호를 기준으로 이어져야 담당자가 후속 처리를 확인할 수 있기 때문입니다.

이 프로젝트를 통해 현장 업무 화면에서 사용자의 입력 흐름과 서버 데이터 흐름을 함께 보며 개발하는 경험을 쌓았습니다. 개발 중인 모바일 동의와 전자서명 기능은 완료된 접수·알림 화면과 분리해 확인하고 있습니다.

## 사용 기술

JavaScript, WebSquare, JSP, jQuery, Java, Spring MVC, MyBatis, MariaDB, REST API, Messaging API
