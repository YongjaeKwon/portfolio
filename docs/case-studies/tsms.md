# 교육용 단말 운영 시스템(TSMS)

서울시교육청 디벗 사업의 교육용 단말 약 11만 대와 배송·설치·A/S·점검 이력을 관리합니다. 화면·API·SQL 개발과 운영 데이터 정리를 맡습니다.

- 백엔드·DB: Java 11 · Spring MVC · MyBatis · MariaDB
- 프론트엔드: JavaScript · WebSquare5 · JSP

## A/S 결과 조회 SQL 개선과 결과 검증

기간을 지정해도 A/S 결과 조회가 느렸습니다. 통합 뷰 대신 기본 테이블을 조인하고 접수별 최신 이력을 직접 조회하도록 SQL을 바꿨습니다. 날짜 컬럼의 함수 적용을 없애고 시작일 이상·종료일 다음 날 미만의 범위로 검색하도록 수정했습니다.

운영 DB에서 검색 조건마다 읽기 전용 트랜잭션을 열어 변경 전후 SQL을 비교했습니다. 조회값·NULL·중복 행과 컬럼 정보를 대조해 결과가 달라지지 않는지 검증했습니다. 개발 DB에서 발견한 취소 상세 누락도 옵티마이저 설정을 바꿔 재현하고 원본 이력과 비교했습니다.

완료월 조회: 약 53초 → 1.2초
전체 조회(약 48만 건): 약 125초 → 44초

## 콜센터 서비스 이력 조회 개선

콜센터에서 고객을 선택하거나 서비스 접수를 마친 뒤 학교 서비스 이력이 늦게 표시됐습니다. 검색 조건으로 범위를 좁히기 전에 전체 접수와 이력을 집계하는 구조가 병목이었습니다.

학교·고객명·전화번호 조건에 맞는 접수를 먼저 찾고 해당 접수의 최신 이력만 조회하도록 목록 SQL을 바꿨습니다. 건수 조회에서는 불필요한 최신 이력 집계를 없애고 이력 존재 여부만 확인했습니다. 묶음 접수의 건수와 기존 검색·권한·페이징 조건은 유지했습니다.

운영 DB에서 검색 조건별로 조회값·NULL·정렬·건수가 같은지 대조한 뒤 운영에 반영했습니다. 기존 이름 검색이 제한 시간을 넘긴 경우에는 범위나 조인 순서를 제한해 결과를 별도로 비교했습니다.

반영 전후 일별 운영 로그에서 조회 API 응답 중앙값이 약 20초에서 0.02초로 줄었습니다. 상담사에게서 접수 후 번호가 표시되기까지의 대기시간도 약 10초에서 1초로 줄었다는 피드백을 받았습니다.

## 종이 점검표와 재방문 기록 전산화

종이 점검표로는 학교별 진행 상황을 파악하기 어려웠습니다. 분실하거나 가져오지 않은 단말은 재방문 때 확인해야 하므로 학교의 완료 여부뿐 아니라 단말별 미완료 사유와 이전 점검 기록이 필요했습니다.

단말마다 점검 회차와 결과를 저장하고 미완료 단말은 사유와 함께 다음 회차로 넘기도록 개발했습니다. 재방문 시 이전 기록을 확인하며 점검을 이어갈 수 있습니다.

일정 승인부터 점검표 작성, 터치 서명, 확인서·결과 파일 발급까지 구현했습니다. 담당자 역할과 진행 상태에 따라 입력 항목을 구분했습니다. 저장할 때 수정 버전을 비교해 다른 담당자가 먼저 저장한 결과를 덮어쓰지 않게 했습니다.

운영 기록: 71개교에서 약 1만 5천 건의 점검 기록 저장

## 일련번호 저장 기준 수정과 운영 데이터 정리

입력용 14자리 일련번호와 전체 15자리 일련번호가 섞여 잘못된 단말에 연결되거나 중복 저장될 수 있었습니다. 이미 점검을 마친 데이터도 있어 결과를 남긴 채 정리해야 했습니다.

저장 기준을 15자리로 통일했습니다. 14자리 입력은 후보를 찾은 뒤 학교 배정 정보로 단말을 확정하게 했습니다. 기존 데이터는 학년·반·번호와 점검 이력으로 중복을 가려내는 SQL로 정리했습니다. 운영 반영 전 백업·롤백 SQL과 반영 후 검증 SQL을 준비했습니다.

운영 DB에 반영했으며 기존 점검 결과를 보존하고 중복 행을 정리했습니다.

## 상담이력 스크롤의 중복 요청 제어

스크롤 중 같은 페이지를 중복 요청하던 화면을 수정했습니다. 요청은 한 번에 하나만 실행하고 검색 조건이 바뀌면 이전 응답을 버린 뒤 마지막 검색을 실행합니다. 다음 페이지에도 고객·검색어·권한 조건을 유지하고 오류 후 재조회하도록 처리했습니다.

실제 화면 함수를 실행하는 테스트에서 연속 스크롤 이벤트 100회를 추가 조회 1회로 처리했습니다. 검색 조건 변경과 오류 후 재시도도 확인했습니다.

## 단말 일괄 등록 전에 오류 확인

엑셀 등록 목록을 생산입고 정보와 대조하고 일련번호 중복을 검사했습니다. 오류가 있으면 원인과 기존 학교·사용자 정보를 알려주고 검증을 통과한 단말은 일괄 등록하도록 했습니다. QR에는 내부 DB 식별자 대신 외부 노출용 ID를 담았습니다.

운영팀의 대량 등록과 공장 전용 프린터 출력 업무에 사용됩니다.

## 외부 연동 유지보수
